# Threat model — STRIDE

Assets: account/session credentials, tenant research and notes, provider keys and credits, public-source integrity, availability and audit records. Attackers include anonymous bots, authenticated hostile tenants, malicious source pages/uploads, compromised dependencies and stolen sessions. The browser, public web, provider responses and user documents are untrusted. The service-role process and cloud account operators are privileged trust boundaries.

| STRIDE                 | Abuse case                                                                               | Mitigation / location                                                                                                               | Evidence and remaining risk                                                                           |
| ---------------------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| Spoofing               | Forged session, unverified account, stolen refresh token                                 | `server/guard.ts`, `server/db.ts`, auth routes; verified identity/email, assurance check, httpOnly cookies, rotation and revocation | Setup bypass negative tests; hosted email/OAuth/MFA and revocation need real integration tests        |
| Tampering              | Cross-tenant IDs, altered job payload, guessed contact, CSV formula                      | RLS/composite FKs, schemas, transactional RPC, `research/verify.ts`, `csv.ts`                                                       | DB isolation, pipeline, CSV and browser tests; service-role code still requires careful manual review |
| Repudiation            | User disputes costly research or account operation                                       | Server-generated audit events, source/time metadata, provider/model/token logs                                                      | Audit helper and DB controls; no immutable external audit sink                                        |
| Information disclosure | SSRF to metadata, DNS rebinding, exported other-tenant data, raw upload leak             | `security/safe-fetch.ts`, pinned IP, redirects rechecked, no credentials; owner filters; transient uploads                          | Malicious URL corpus + real transport + RLS tests; external provider retention requires contracts     |
| Denial of service      | Large bodies, decompression bombs, slow servers, PDF resource exhaustion, duplicate jobs | Bounded streams, 7-second crawl deadline, PDF worker ceiling, Redis limits, lease/attempt caps                                      | Transport/upload/DB tests; distributed infrastructure and aggregate concurrency need load testing     |
| Elevation of privilege | Model obeys website commands, browser imports service key, cron called anonymously       | No model side-effect tools; evidence verification; server-only boundary/lint; bearer cron secret; service-only RPC grants           | Prompt-injection fixtures, secret scan, negative API tests; semantic model errors remain possible     |

## Highest-risk paths

SSRF controls must remain centralized: never call raw HTTP transport with model-supplied URLs. `nodeTransport` is exported for local HTTP tests, not an authorization boundary. Every production caller uses `SafeFetchProvider`. All DNS answers must pass the address policy; the selected address is pinned through the socket lookup. Redirect and robots destinations are checked again. Robots permission is not a legal license; website terms still need operator review.

Model schemas constrain structure, not truth. Exact quotation checks prove that text appears in a stored source, not that the source is honest or that the interpretation is correct. Reasoning has no tools that send messages, modify accounts or spend outside quota-wrapped adapters. Search snippets can be stale; affiliations remain unconfirmed unless supported by company-page role evidence.

Trust in Vercel, Supabase, Redis, Gnani and the chosen reasoning/search service includes their account permissions, backups, logs and regional processing. No local unit test proves those systems' production configuration. Review credentials and least privilege before launch; test restore and account deletion against actual infrastructure.
